# Техническое задание: Ambient Player (рабочее название — «Aura»)

**Версия:** 1.0 (MVP на Python)
**Платформа:** Windows 10/11
**Стек:** Python 3.11+, PyQt6/PySide6, SQLite, librosa, yt-dlp, sounddevice

---

## 1. Общее описание проекта

**Aura** — интеллектуальный фоновый плеер, который автоматически подбирает эмбиент/музыку под текущую активность пользователя в реальном времени. Система анализирует активное окно, интенсивность ввода (клавиатура/мышь) и на основе этого выбирает треки из локальной библиотеки. Пользователь может обучать систему лайками/дизлайками прямо с панели задач.

**Ключевая идея:** тишина и музыка — это тоже часть работы. Система должна понимать, когда музыка мешает (например, вы смотрите YouTube) и когда она нужна (сосредоточенная работа в IDE).

## 3. Функциональные модули

### 3.1. Библиотека треков (Library Manager)

**Хранение:** SQLite (`aura.db`), файлы треков — в `%APPDATA%/Aura/library/`.

**Структура данных:**

```
Pack (пак/плейлист)
├── id: UUID
├── name: str
├── source: "youtube" | "local" | "generated"
├── source_url: str | null
├── enabled: bool (вкл/выкл целиком)
├── created_at: datetime
└── tracks: [Track]

Track
├── id: UUID
├── pack_id: UUID (FK)
├── title: str
├── artist: str | null
├── file_path: str
├── duration_sec: int
├── format: str
├── analysis: TrackAnalysis
└── enabled: bool (отдельный трек можно выключить)

TrackAnalysis
├── bpm: float
├── energy: float (0..1)
├── valence: float (0..1, «позитивность»)
├── danceability: float
├── acousticness: float
├── instrumentalness: float
├── loudness_db: float
├── key: str | null
├── mood_tags: [str] (напр. ["calm", "dark", "spacey"])
└── analyzed_at: datetime
```

**Операции:**
- Создание/удаление/переименование пака.
- Включение/выключение пака целиком (глобальный тумблер, влияет на выбор треков).
- Включение/выключение отдельного трека внутри пака.
- Импорт локальной папки (сканирование рекурсивно, определение форматов).
- Перемещение треков между паками (drag-n-drop).

### 3.2. Импорт с YouTube

**Библиотека:** `yt-dlp` + `ffmpeg` (для конвертации в m4a/opus).

**Два сценария:**

1. **Один трек:** вставляешь ссылку `youtube.com/watch?v=...` → скачивается аудио, создается Track.
2. **Плейлист:** вставляешь ссылку `youtube.com/playlist?list=...` → создается новый Pack, скачиваются все треки.

**UI-поток:**
- Кнопка «+ Добавить с YouTube» в главном окне.
- Диалог: поле для URL + выбор пака (существующий или «создать новый»).
- Прогресс-бар с отменой.
- Опция «Скачать только аудио» (всегда включена для экономии).

**Технические детали:**
- Формат загрузки: `bestaudio[ext=m4a]/bestaudio`.
- Постобработка: `FFmpegExtractAudio` → opus/m4a.
- Метаданные извлекаются из `info.json` (title, uploader, duration).
- Если трек > 15 минут — предупреждение (долгая загрузка).
- Параллельная загрузка: 2-3 потока максимум (иначе бан YouTube).

### 3.4. Activity Monitor (слежение за активностью)

**Что отслеживается:**

| Сигнал | Источник | Частота |
|--------|----------|---------|
| Активное окно | `pywin32` (`GetForegroundWindow`) | 2 Гц |
| Заголовок окна | `GetWindowText` | 2 Гц |
| Имя процесса | `psutil` по PID | 2 Гц |
| Нажатия клавиш | `pynput.keyboard` (глобальный хук) | realtime |
| Клики/движение мыши | `pynput.mouse` | realtime |
| Звук из других приложений | `pycaw` (Windows Audio Session API) | 1 Гц |
| Время бездействия | `GetLastInputInfo` | 1 Гц |

**Производные метрики (пересчитываются раз в 5 сек):**

- `keys_per_minute` — интенсивность печати.
- `mouse_activity` — уровень движения мыши (0..1).
- `idle_seconds` — время с последнего ввода.
- `foreign_audio` — bool, играет ли звук из другого приложения (Chrome, игра).
- `current_context` — агрегат: `(process_name, window_title_pattern)`.

**Black/White списки приложений:**

```
AppRule
├── process_name: str  (напр. "chrome.exe")
├── title_pattern: str | null  (regex, напр. ".*YouTube.*")
├── mode: "blacklist" | "whitelist" | "custom"
├── custom_pack_ids: [UUID] | null  (для mode=custom)
├── pause_behavior: "pause" | "duck" | "ignore"
└── priority: int
```

**Примеры правил:**
- `chrome.exe` + `.*YouTube.*` → `pause` (свой звук).
- `cyberpunk2077.exe` → `pause` (не мешать игре).
- `code.exe` / `pycharm64.exe` → `whitelist` (музыка приветствуется).
- `zoom.exe` → `duck` (приглушить на 80%).
- `telegram.exe` → `custom` с паком «Lo-fi».

### 3.5. Playback Controller (аудио-движок)

**Библиотека:** `sounddevice` + `pydub`/`ffmpeg` для декодирования. Альтернатива: `pygame.mixer` (проще, но менее гибко).

**Функции:**
- Воспроизведение MP3, FLAC, OGG, Opus, M4A, WAV.
- Кроссфейд между треками (1–3 сек, настраивается).
- Плавное изменение громкости (fade in/out за N мс).
- Ducking: при появлении внешнего звука — громкость падает до X% за 500 мс.
- Пауза при сворачивании приложения (опционально, настраивается).
- Тишина между треками: случайный интервал `[min_silence, max_silence]` сек, во время которого играет «атмосферный» трек из пака `Ambient Only` (дождь, ветер, гул).

**Состояния плеера:**
```
IDLE → LOADING → PLAYING → FADING_OUT → SILENCE → PLAYING → ...
                              ↓
                           PAUSED
```

### 3.6. Интеллектуальная система выбора треков (AI Scheduler)

Это ядро проекта. Задача: по текущему контексту (окно, активность, время, история) выбрать следующий трек так, чтобы максимизировать долгосрочное удовольствие пользователя (лайки) и минимизировать раздражение (дизлайки, ручные паузы).

#### Вариант A: Контекстные бандиты (Contextual Bandits) — **рекомендуемый для MVP**

**Идея:** для каждого контекста храним оценки треков. При выборе — эксплуатируем лучшие, иногда исследуем новые (ε-greedy или Thompson Sampling).

**Контекст:** кортеж `(process_name, activity_level, time_of_day)`.
- `activity_level`: `idle | low | medium | high` (по keys_per_minute + mouse_activity).
- `time_of_day`: `morning | day | evening | night`.

**Оценка трека:** `score = avg_rating + α * novelty_bonus - β * repetition_penalty`.

**Алгоритм:** Thompson Sampling с Beta-распределением по лайкам/дизлайкам.

**Плюсы:** простой, быстрый, работает сразу, легко объяснить.
**Минусы:** не обобщает между похожими треками.

#### Вариант B: Learning-to-Rank на признаках

**Идея:** обучаем модель (LightGBM/XGBoost) ранжировать треки по признакам.

**Признаки:**
- `track.energy`, `track.valence`, `track.bpm`, `track.loudness`.
- `context.process_name`, `context.activity_level`.
- `history: играл ли этот трек в этом контексте, с каким рейтингом`.
- `time_since_last_play`, `play_count`.

**Обучение:** офлайн, раз в N дней, на накопленных лайках/дизлайках.
**Инференс:** realtime, выбор top-1 из отфильтрованных треков.

**Плюсы:** обобщает, учитывает признаки.
**Минусы:** нужны данные (холодный старт), сложнее в отладке.

#### Вариант C: Reinforcement Learning (DQN / PPO)

**Идея:** агент учится выбирать треки, максимизируя награду (лайк +1, дизлайк −2, пропуск −1, конец трека без реакции 0).

**Состояние:** вектор из признаков контекста + эмбеддинг текущего трека.
**Действие:** выбрать трек из top-K кандидатов (не из всей библиотеки — иначе огромное пространство).
**Награда:** сумма лайков/дизлайков за сессию.

**Плюсы:** теоретически оптимально, адаптируется.
**Минусы:** сложно, нужны тысячи взаимодействий, риск «сойти с ума» и играть только дизлайки из-за плохой функции награды.

#### Вариант D: Гибрид (рекомендуемый финал)

- **Фильтр 1:** правила (black/white списки, ducking).
- **Фильтр 2:** контекстный бандит (Вариант A) — быстрый, адаптивный.
- **Ранжировщик:** LightGBM (Вариант B) — поверх бандита, если данных достаточно.
- **RL:** опционально, как «долгосрочный стратег» (Вариант C).

**Интерфейс переключения:**

```python
class SchedulerBackend(ABC):
    @abstractmethod
    def select_next(self, context: Context, candidates: list[Track]) -> Track: ...

class EpsilonGreedyBandit(SchedulerBackend): ...
class ThompsonSamplingBandit(SchedulerBackend): ...
class LightGBMRanker(SchedulerBackend): ...
class DQNAgent(SchedulerBackend): ...
```

Переключение — в настройках, без перезапуска (фабрика + сохранение состояния).

### 3.7. Feedback Manager (лайки/дизлайки)

**Сбор:** кнопки в панели задач (см. UI) + горячие клавиши (`Ctrl+Alt+L`, `Ctrl+Alt+D`).

**Запись:**

```
Feedback
├── id: UUID
├── track_id: UUID
├── context_snapshot: Context (JSON)
├── rating: -1 | +1
├── timestamp: datetime
├── session_id: UUID
└── position_in_track_sec: float
```

**Использование:**
- Обновление бандита (Beta-распределение).
- Обучение ранжировщика (офлайн, раз в сутки).
- Персональный «профиль вкуса» — агрегат по mood_tags.

## 4. Интерфейс (UI)

### 4.1. Main Window (главное окно)

**Стиль:** тёмный минимализм, акценты — неоновые градиенты (переливы от фиолетового к синему), анимации 60 FPS.

**Вкладки/секции:**

1. **Сейчас играет:**
   - Обложка (или анимированный визуализатор спектра).
   - Название, артист, пак.
   - Прогресс-бар с кроссфейдом.
   - Кнопки: play/pause, next, prev, like, dislike, mute.
   - Текущий контекст: «Активно: PyCharm — activity: high — mode: focus».

2. **Библиотека:**
   - Дерево: Packs → Tracks.
   - Чекбоксы вкл/выкл у паков и треков.
   - Кнопка «+ Добавить с YouTube».
   - Кнопка «Сканировать папку».
   - Поиск/фильтр по mood_tags, BPM, energy.

3. **Правила:**
   - Таблица AppRules (edit/add/remove).
   - Drag-n-drop паков на приложения (визуально).

4. **Аналитика:**
   - Графики: лайки/дизлайки по времени, топ-треков, распределение по контекстам.
   - «Карта вкуса» — scatter plot energy×valence с цветом = рейтинг.

5. **Настройки:**
   - Выбор AI-бэкенда (A/B/C/D).
   - Кроссфейд, длительность тишины, порог ducking.
   - Горячие клавиши.
   - Экспорт/импорт БД.

### 4.2. Taskbar Panel (панель задач)

**Технически:** трей-иконка + отдельное окно без рамки (`Qt.FramelessWindowHint`), прикрепленное к панели задач через `ITaskbarList3` (через `pywin32`).

**Элементы:**

- **Кнопка Play/Stop** — запускает/останавливает всю систему (не только трек).
- **При воспроизведении:** вторая кнопка (hover → всплывает панель):
  - ❤️ Лайк
  - 👎 Дизлайк
  - ⏭ Пропустить
  - ⏸ Пауза на 15 мин
- **Индикатор:** цветная точка (зеленая — играет, желтая — тишина, красная — пауза из-за внешнего звука).

**Поведение:**
- Панель всегда поверх остальных окон.
- Не мешает кликам по другим приложениям (transparent для мыши вне кнопок).
- Анимация появления hover-меню: плавное выезжание + затухание.

## 8. Безопасность и приватность

- **Никакой телеметрии.** Все данные — локально в `%APPDATA%/Aura/`.
- **Логи:** только опционально, с явным согласием, хранятся 7 дней, потом удаляются.
- **Сетевой доступ:** только yt-dlp (для загрузки) и ничего больше. Можно отключить полностью.
- **Логирование активности:** хранится только агрегат (keys_per_minute), не сами нажатия. Заголовки окон — только для сопоставления с правилами, не сохраняются в БД (кроме момента выбора трека, анонимизированно).
